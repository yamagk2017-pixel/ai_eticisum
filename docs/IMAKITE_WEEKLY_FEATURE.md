# イマキテアイドル：ジャパンの紹介欄

`/imakite/weekly` のSpotifyプレーヤーの下に、カバーアイドルと続く2組を掲載する。プレーヤーは従来の高さ552pxに戻し、プレーヤー内で曲一覧をスクロールする。

紹介は囲み枠・背景のないレイアウト。カバー画像は256px、続く2組は128px（640px未満では80px）。続く2組は画面幅にかかわらず縦に積み、各組は左に画像、右に本文を並べる。カバーは768px以上で左右配置、それ未満は画像の下に本文を置く。公式リンクも囲みを外したテキストリンクとして表示する。

## 取得元・表示条件

- サーバー環境変数 `NEXT_PUBLIC_SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` が必要。後者は公開用変数にしない。
- `ihc.release_playlist_projects.spotify_playlist_id = '6ACBBRFex0KOvF1V82ppvH'` から企画のslugを解決。
- 対象企画の `ihc.release_playlist_runs` から `status = 'committed'` かつ `committed_at IS NOT NULL` の最新行を取得する。確定日時降順、同時刻はcutoff降順。
- `target_tracks` の先頭から3組。重複グループは最初の掲載曲を採用する。初期実装時の選曲処理は1組1曲。
- `group_id` で `imd.groups` の名前・画像、`imd.group_profiles` の日本語本文、`imd.external_ids` の登録済みURLを取得する。NANDATTE詳細APIと同じ情報源。
- 紹介文は書き換えず改行も保持。200文字を超える場合は「続きを読む」で全文を表示する。
- 未登録の値は省略。外部IDからURLを組み立てない。リンクはHTTP(S)のみ。
- 確定行がない場合や取得障害時は紹介欄を省略し、既存プレーヤーとアーカイブ導線を表示する。取得障害はサーバーログへ記録する。

## 更新・キャッシュ

ページは `connection()` によりリクエスト時に描画し、この機能の全Supabase読み取りに `cache: 'no-store'` を指定する。HTMLの静的生成や期限付きデータキャッシュは使わない。

週次更新がDBで確定した後の次回ページ読み込みから、新しい先頭3組と掲載曲に切り替わる。反映待ちのキャッシュ時間は0秒（実際の応答には通常の通信・DB取得時間がかかる）。開いたままのページは再読み込みが必要。プロフィール編集も次回読み込みから反映する。Webhook、再ビルド、週次処理の再実行は不要。

未確定の新しいrunが存在しても、直近の確定runを表示する。管理テーブルの本文・選曲根拠・キーをブラウザへ渡さず、紹介に必要な項目だけを描画する。
